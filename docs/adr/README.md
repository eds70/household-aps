## Что такое ADR

**ADR (Architecture Decision Record)** — короткий документ, фиксирующий важное архитектурное решение, его контекст и последствия.

**Зачем:**
- Сохранить историю решений.
- Объяснить «почему так, а не иначе» для будущих разработчиков.
- Избежать повторного обсуждения уже принятых решений.

**Когда создавать ADR:**
- Выбор технологии (БД, solver, фреймворк).
- Изменение архитектуры (новая таблица, новый паттерн).
- Отказ от альтернативы (почему не Gurobi, не soft-delete).
- Компромисс (2 транзакции вместо savepoint).

**Когда НЕ создавать ADR:**
- Мелкие баг-фиксы.
- Рефакторинг без изменения архитектуры.
- Изменения в UI без архитектурных последствий.

## Формат ADR

### Структура

```markdown
# NNNN. Название решения

**Дата:** YYYY-MM-DD
**Статус:** Принято | Отклонено | Заменено | Устарело
**Контекст:** Итерация N

## Контекст

Описание проблемы, которая требует решения. Какие силы влияют?
Какие ограничения? Что известно на момент принятия решения?

## Решение

Описание принятого решения. Что именно сделано?
Как это работает?

## Последствия

### Положительные

- ...

### Отрицательные

- ...

### Альтернативы

- **Альтернатива 1:** почему отклонена.
- **Альтернатива 2:** почему отклонена.

## Ссылки

- [docs/ARCHITECTURE.md](../ARCHITECTURE.md)
- [README.md](../../README.md)
```

### Статусы

| Статус | Значение |
|--------|----------|
| **Принято** | Решение действует |
| **Отклонено** | Решение не принято |
| **Заменено** | Заменено другим ADR |
| **Устарело** | Больше не актуально |

### Именование

`NNNN-<краткое-название>.md`, где `NNNN` — четырёхзначный номер (0001, 0002, ...).

**Примеры:**
- `0001-use-ortools-cp-sat.md`
- `0002-snapshot-tables-for-versioning.md`
- `0003-plan-settings-per-plan.md`
- `0004-whatif-two-transactions.md`

### Краткое описание

#### [0001. Use OR-Tools CP-SAT](0001-use-ortools-cp-sat.md)

**Проблема:** какой solver использовать для планирования?

**Решение:** OR-Tools CP-SAT.

**Альтернативы:** Gurobi, собственный solver.

**Итерация:** 1.

---

#### [0002. Snapshot tables for versioning](0002-snapshot-tables-for-versioning.md)

**Проблема:** как версионировать справочники?

**Решение:** снапшоты (`schedule_version` + `scheduled_task`).

**Альтернативы:** soft-delete, audit log.

**Итерация:** 1.

---

#### [0003. Plan settings per plan](0003-plan-settings-per-plan.md)

**Проблема:** глобальные настройки применяются ко всем планам одновременно.

**Решение:** `plan_settings` — снапшот настроек для каждого плана.

**Альтернативы:** JSONB-поле в `schedule_version`, отдельная таблица без триггера.

**Итерация:** 13.14.

---

#### [0004. What-if two transactions](0004-whatif-two-transactions.md)

**Проблема:** как запустить what-if без изменения БД?

**Решение:** 2 транзакции (rollback + commit).

**Альтернативы:** savepoint, отдельная БД, копирование данных.

**Итерация:** 12.

## Как добавить ADR

### 1. Создать файл

`docs/adr/NNNN-<название>.md`, где `NNNN` — следующий номер.

### 2. Заполнить по формату

См. [Формат ADR](#формат-adr).

### 3. Обновить индекс

Добавить строку в таблицу [Индекс ADR](#индекс-adr):

```markdown
| 0005 | [Новое решение](0005-new-decision.md) | Принято | 2026-10-01 | 14 |
```

### 4. Добавить краткое описание

```markdown
#### [0005. Новое решение](0005-new-decision.md)

**Проблема:** ...

**Решение:** ...

**Альтернативы:** ...

**Итерация:** 14.
```

### 5. Обновить CHANGELOG

```markdown
### Added
- ADR 0005: Новое решение.
```

### 6. Обновить ARCHITECTURE.md (если нужно)

Если ADR меняет архитектуру — добавить ссылку в `docs/ARCHITECTURE.md`.
