# BACKLOG.md

Реестр задач на будущее развитие APS Production Scheduler: доработки,
технический долг, улучшения UX, архитектурные идеи.

**Формат:** таблица с колонками «#», «Задача», «Объём», «Приоритет».

**Приоритеты:**
- 🔥 — критично для следующего релиза.
- 🟡 — средний приоритет, войдёт в ближайшие спринты.
- 🟢 — низкий приоритет, «когда-нибудь».
- ⏳ — исследование / отложено до выяснения.

**Обозначения объёма:** `2ч`, `4ч`, `1д`, `2д`, `1нед`, `2нед` — оценка
в рабочих часах/днях одного разработчика.

## 1. Рецептуры и снапшоты

| # | Задача | Объём | Приоритет | Описание |
|---|--------|-------|-----------|----------|
| 1.1 | Валидация `qty_per_base > 0` | 2ч | 🟡 | В `RecipeItemBase.qty_per_base` (`backend/app/api/v1/material_models.py`) добавить `Field(gt=0)`. Сейчас можно ввести `0` или отрицательное значение. Backend должен отклонять `422`, UI — показывать ошибку. |
| 1.2 | UNIQUE `(recipe_id, material_id)` | 4ч | 🟡 | Запретить дублирование одного материала в рецепте. Миграция `add_30_recipe_item_unique.sql` + обработка `409 Conflict` в `RecipesPage.tsx` (снекбар «Материал уже в рецепте»). |
| 1.3 | Inline-edit `product_id` в рецепте | 1д | 🟢 | Сейчас привязанный продукт меняется только через удаление/создание рецепта. Добавить `agSelectCellEditor` со списком `products.filter(type === 'PF')` в основную таблицу `RecipesPage.tsx`. |
| 1.4 | `material_snapshot` | 2д | 🟡 | Материалы **не версионируются**. При открытии старой версии имя материала — текущее (JOIN с живой таблицей). Нужны `material_snapshot` + `material_item_snapshot` по паттерну `recipe_snapshot` (см. ADR 0006). Миграция + блоки в `snapshot.py::snapshot_all_catalogs` + чтение в `materials.py` + `MaterialsPage.tsx`. Требует ADR 0007. |
| 1.5 | Плашка «снапшот не сохранён» | 2ч | 🟢 | В `RecipesPage.tsx` — если у версии пустой `recipe_snapshot` (старые версии до `add_29`), показывать info-баннер вместо пустого списка. |
| 1.6 | Backfill снапшотов для старых версий | — | ⏳ | Технически невозможно: нет данных о составе рецепта на момент создания старой версии. Решение — только создание новых версий. Можно рассмотреть как «невозможно» и закрыть. |

## 2. Справка и подсказки

| # | Задача | Объём | Приоритет | Описание |
|---|--------|-------|-----------|----------|
| 2.1 | Полнотекстовый поиск в справке | 1д | 🟡 | Сейчас `/api/v1/help/search` — простой `ILIKE` по `title`/`content_md`/`tags`. Мигрировать на `tsvector` + GIN-индекс. Актуально при 100+ статьях. См. ADR 0005. |
| 2.2 | Редактирование подсказок через UI | 1д | 🟢 | Сейчас `help_hint` правится только через SQL / seed. Добавить CRUD-эндпоинты (по паттерну `help_article` в Итерации 15.5) + `HintEditor.tsx` на странице «Помощь». |
| 2.3 | Per-user прогресс туториала | 1д | 🟢 | Прогресс в `localStorage` (per-browser). Перенести в `app_user` (поле `tutorials_completed JSONB`). При выходе из системы — прогресс сохраняется на сервере. |
| 2.4 | Аналитика прохождения туров | 4ч | 🟢 | Логировать `tour_id`, `step_index`, `event` (`started`/`skipped`/`completed`) в таблицу `tutorial_event`. Дашборд по прохождению (какие шаги пропускаются). |
| 2.5 | Валидация внутренних ссылок | 4ч | 🟢 | При сохранении статьи через `POST/PUT /help/articles` проверять, что все `/help/{slug}` в `content_md` ведут на существующие статьи. Возвращать `400` с перечнем «битых» ссылок. |

## 3. Аудит и мониторинг

| # | Задача | Объём | Приоритет | Описание |
|---|--------|-------|-----------|----------|
| 3.1 | Realtime-обновление аудита | 1д | 🟢 | SSE или WebSocket — новые события появляются без обновления страницы. Особенно полезно для наблюдения за работой лаборатории / ЧЗ. |
| 3.2 | Метрики Prometheus | 1д | 🟢 | `/metrics` эндпоинт + библиотека `prometheus_client`. Метрики: RPS, latency, error rate, размер БД, количество активных версий. |
| 3.3 | OpenTelemetry трейсинг | 1д | 🟢 | Трейсы запросов, включая solver. Для отладки медленных операций. Интеграция с Jaeger / Tempo. |
| 3.4 | Отчёт за период в PDF | 2д | 🟢 | PDF с шапкой, графиками и таблицей событий. `weasyprint` (HTML → PDF) или `reportlab` (программная генерация). |
| 3.5 | Shared views аудита | 1д | 🟢 | Сейчас `audit_saved_view` — per-user. Добавить `is_shared BOOLEAN` + доступ для других пользователей организации. UI: переключатель «Поделиться» в редакторе представления. |
| 3.6 | Кастомные цвета/иконки saved views | 4ч | 🟢 | В таблице `audit_saved_view` — колонки `color VARCHAR(20)` и `icon VARCHAR(50)`. В UI — выбор при создании. Чипы представлений окрашены. |

## 5. Крупные фичи

| # | Задача | Объём | Приоритет | Описание |
|---|--------|-------|-----------|----------|
| 5.1 | MCP-сервер filesystem | 1–2д | 🟢 | Для AI-ассистента — доступ к файлам проекта через MCP-протокол. Упростит передачу контекста. См. ADR 0006 идеи. |
| 5.2 | Управление организациями через UI | 2д | 🟢 | Мульти-тенантность сейчас «плоская» (одна организация). Добавить CRUD организаций для супер-админа + переключатель организации в шапке. |
| 5.3 | Прогнозирование спроса (ML) | 2нед | 🟢 | Интеграция с моделью прогноза для `production_order.target_qty`. Обучение на исторических заказах. |
| 5.4 | Многопользовательское редактирование (CRDT) | 2нед | 🟢 | Совместная работа над планом в реальном времени. Yjs или Automerge. Сложно, но актуально при большой команде. |
| 5.5 | Мобильное приложение (PWA) | 3нед | 🟢 | Мастер смены на планшете. PWA быстрее, но ограничения по offline. |
| 5.6 | Интеграция с ERP (1С) | 2нед | 🟡 | Двусторонняя синхронизация заказов, остатков, фактов. Через REST API или прямую работу с БД 1С. |
| 5.7 | Realtime-обновление плана | 1нед | 🟢 | Если несколько пользователей одновременно правят план — конфликты. Сейчас нет (один человек за раз). Добавить optimistic locking. |
| 5.8 | Мульти-тенантный ЧЗ-API | 1д | 🟢 | Привязка API-ключа к организации (`app_settings.cz_api_key_org_id`). Сейчас `POST /cz/scan` жёстко использует `DEFAULT_ORG_ID` (см. фикс 4.10.2, `docs/TROUBLESHOOTING.md` п. 156). Актуально, если камеры ЧЗ будут слать сканы от имени **нескольких организаций**. Реализация: миграция + чтение `cz_api_key_org_id` при валидации ключа + UI в «Настройки → ЧЗ» для управления привязкой. |

## 6. Технический долг

| # | Задача | Объём | Приоритет | Описание |
|---|--------|-------|-----------|----------|
| 6.1 | Full-text search по `help_hint` | 4ч | 🟢 | Если подсказок станет 50+, `ILIKE` будет медленным. Пока не критично. |
| 6.2 | Очистка `\r\n` в `help_article.content_md` | 1ч | 🟢 | Артефакт применения через PowerShell. Есть команда очистки в `docs/OPERATIONS.md`. На рендер не влияет. |
| 6.3 | Пагинация API | 1д | 🟡 | Сейчас все списки возвращаются целиком. При 1000+ записях в `audit_log` или `material_stock_log` — проблема. Ввести `limit`/`offset` по умолчанию в `GET /audit/log`. |
| 6.4 | Кэш `/api/v1/help/hints` | 2ч | 🟢 | Фронт грузит один раз, но backend делает SQL каждый раз. Можно кэшировать на 5 мин (`functools.lru_cache` или Redis). |
| 6.5 | Rate limiting | 4ч | 🟢 | Сейчас нет ограничений на частоту запросов. Для `/cz/scan` (приём от камер) — может быть критично. `slowapi` или самописный middleware. |
| 6.6 | Тесты для `recipes.py` | 4ч | 🟡 | Нет отдельных тестов на новые эндпоинты Итерации 17.1–17.2 (`PUT /items/{id}`, `POST /items`, `GET /?version_id`). Изменения проверялись вручную. Добавить `tests/test_recipes.py` + `tests/test_recipes_snapshots.py`. |
| 6.7 | Тесты для `snapshot.py` (recipe-блоки) | 2ч | 🟡 | Нет тестов на новые блоки 5 и 6 в `snapshot_all_catalogs`. Проверять, что при создании версии заполняются `recipe_snapshot` / `recipe_item_snapshot`. |

## Отменённые задачи

Задачи, которые обсуждались, но были отменены или отложены бессрочно.

| # | Задача | Причина |
|---|--------|---------|
| O.1 | Backfill снапшотов для старых версий планов | Технически невозможно — нет данных о составе рецепта на момент создания старой версии |
| O.2 | Автоматическое создание ADR при мердже PR | Излишне — ADR пишутся осознанно, не автоматически |
| O.3 | `--grep PATTERN` в `collect_project.py` | Отложено — базового набора `--path` / `--files` / `--outline` достаточно для 95% сценариев |
| O.4 | `--split-by-dir` в `collect_project.py` | Отложено — пока не требуется |
| O.5 | `--json` в `collect_project.py` | Отложено — не нужно |
| O.6 | Отдельная страница «Отчёты» | Избыточна — экспорт в Excel и дашборд покрывают 90% сценариев |
| O.7 | `max_rows` без ограничений в `/audit/export.xlsx` | Оставлен потолок 100 000 — защита от гигантских выгрузок |
