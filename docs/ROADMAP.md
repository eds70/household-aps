### Итерация 17.1 — Inline-edit рецептур в UI (✅)

**Проблема:**
Модуль «Рецептуры» позволял только создать рецепт (с пустым составом)
и удалить его. Не было:
- редактирования базовых полей (`base_volume_kg`, `comment`);
- редактирования состава (добавить/удалить/изменить количество);
- режима просмотра (readonly) для сохранённых версий плана.

**Что сделано:**

**Backend (`recipes.py`):**
- `PUT /api/v1/recipes/{recipe_id}/items/{item_id}` — новый эндпоинт
  для inline-edit `qty_per_base`.
- `POST /api/v1/recipes/{recipe_id}/items` переведён на **JSON body**.
- Во все item-endpoint'ы добавлена проверка принадлежности рецепта организации.

**Frontend (`RecipesPage.tsx`):**
- Inline-edit колонок `base_volume_kg` и `comment` в основной таблице.
- Диалог состава — редактируемый AG Grid:
  inline-edit `qty_per_base`, кнопки удаления, форма добавления.
- Режим просмотра: `isReadOnly` через `currentVersionId`.
- `markPlanDirty()` на все изменения.

**Frontend (`api.ts`):**
- `recipesApi.addItem` переведён на JSON body.
- Добавлен `recipesApi.updateItem`.

**Fixed (предсуществующий баг):**
- Селект «Продукт (ПФ)» использовал `materials` вместо `products` →
  FK violation при создании рецепта через UI. Заменено на
  `productsApi.getAll()` с фильтром `type === 'PF'`.

### Итерация 17.2 — Версионирование рецептур (снапшоты) (✅)

**Проблема:**
Рецептуры не версионировались. При открытии сохранённой версии плана
всегда читались **актуальные** данные из `recipe` / `recipe_item`.

**Что сделано:**

**Миграция `add_29_recipe_snapshots.sql`:**
- `recipe_snapshot` — составной PK `(id, version_id)`, FK на
  `schedule_version` с CASCADE.
- `recipe_item_snapshot` — то же.
- FK на `product` / `material` убраны — снапшот имутабелен.

**`snapshot.py`:**
- В `snapshot_all_catalogs` добавлены блоки 5 (recipe) и 6 (recipe_item).
- `stats` содержит `recipes` и `recipe_items`.

**`recipes.py`:**
- `GET /api/v1/recipes/?version_id=<UUID>` — читает из снапшота.
- Все мутации — только с живыми таблицами.

**Frontend:**
- `RecipesPage.loadData` передаёт `currentVersionId`.
- `recipesApi.getAll(productId?, versionId?)`.

**Проверено:**
- Создание версии → `recipe_snapshot` содержит 4 рецепта / 14 компонентов
  для тестовой версии.
- Просмотр версии → данные из снапшота.
- Редактирование в текущем плане не влияет на версию.

### Итерация 17.3 — Дата начала планирования в UI (✅)

**Проблема:**
Настройка `planning_start_date` существовала в backend, но её можно
было изменить только через раздел «Настройки».

**Что сделано:**

**`SchedulePage.tsx`:**
- Стейт `planningStartDate` (`YYYY-MM-DD`).
- `loadPlanningSettings` читает `planning_start_date` из `app_settings`.
- `savePlanningSettings` дополняет до `YYYY-MM-DDTHH:mm:ss`
  (`T08:00:00`) и сохраняет.
- Поле `TextField type="date"` в панели «Параметры расчёта».
- Выравнивание: обёртка кнопки `height: 40`, `alignItems: flex-start`.

**Почему `T08:00:00`:** `core.py::_resolve_t0` парсит значение как
`Europe/Moscow`. Без времени получилось бы `00:00:00 МСК` →
`21:00 UTC` предыдущего дня. С `T08:00:00` — `05:00 UTC`, совпадает
с дефолтом `2026-09-01 05:00:00 UTC`.

### Итерация 19 — Оптимизация заказов и Архивация (✅)

**Цель:** дать пользователю возможность оптимизировать партии
и навести порядок в истории планов.

**Что сделано:**

**19.1. Эндпоинт `auto-split-optimized`.**

**19.2. UI для оптимизации заказов.**

## Отменённые фичи

### Отменено в Итерации 17

- **Автоматическое создание снапшотов для старых версий.**
  Отложено: при открытии версии до `add_29_recipe_snapshots.sql` список
  рецептов просто пуст. Миграция «задним числом» невозможна, потому что
  нельзя восстановить состав рецепта на момент создания старой версии.
- **`material_snapshot`.** Отложено на 18+: материалы не версионируются,
  что приводит к отображению текущих имён в старых версиях.
- **Редактирование `product_id` в inline-edit.** Отложено: `product_id` —
  FK, менять его через AG Grid небезопасно (нужен dropdown-редактор).

### Отменено в Итерации 16

- **Отдельная страница «Отчёты»** — избыточна: экспорт в Excel
  и дашборд покрывают 90% сценариев.
- **`max_rows` без ограничений** — оставлен потолок 100 000,
  чтобы случайная выгрузка не положила backend.

### Отменено в Итерации 15.6

- **`--grep PATTERN`** в `collect_project.py` — фильтр по содержимому.
  Отложено: базового набора `--path` / `--files` / `--outline` достаточно
  для 95% сценариев.
- **`--split-by-dir`** — разбиение дампа по директориям.
  Отложено: пока не требуется.
- **`--json`** — вывод оглавления в JSON.
  Отложено: не нужно.

### Отменено ранее

- **`_build_and_save`** в `WhatIfRunner` — заменено на 2 транзакции
  (Итерация 12, fix).
- **`_RollbackSavepoint`** — заменено на `session.rollback()`.
- **Savepoint-подход** — не работает стабильно с asyncpg + SQLAlchemy 2.0.
