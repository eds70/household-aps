и несколько блоков на один файл.

ПРАВИЛО 3. ЕСЛИ ХОТЬ ГДЕ-ТО ВНУТРИ ЕСТЬ ``` — ВНЕШНИЙ БЛОК ТОЛЬКО ````.
─────────────────────────────────────────────────────────────────
Перед публикацией КАЖДОГО файла проверь мысленно:
  — Есть ли внутри файла хотя бы одна строка, начинающаяся с ```?
  — Если ДА  → внешний codefence ОБЯЗАН быть ```` (четыре кавычки).
  — Если НЕТ → можно ``` (три кавычки), но ```` тоже допустимо.

Сомневаешься — всегда используй ````.

ПРАВИЛО 4. ЯЗЫК CODEFENCE.
─────────────────────────────────────────────────────────────────
  — Markdown-файлы      → `markdown` (или `md`).
  — SQL-файл целиком    → `sql`.
  — JSON-файл целиком   → `json`.
  — Всё остальное       → `markdown`.

Язык указывается СРАЗУ после открывающих кавычек внешнего codefence.

ПРАВИЛО 5. ЗАГОЛОВОК ФАЙЛА — СТРОГО ОТДЕЛЬНОЙ СТРОКОЙ ПЕРЕД CODEFENCE.
─────────────────────────────────────────────────────────────────
Формат (ровно так, без отклонений):
  ## Файл N: <путь/к/файлу>

Примеры:
  ## Файл 1: README.md
  ## Файл 2: CHANGELOG.md
  ## Файл 11: docs/adr/README.md

ПРАВИЛО 6. ВНУТРИ CODEFENCE — РОВНО СОДЕРЖИМОЕ ФАЙЛА. НИЧЕГО ЛИШНЕГО.
─────────────────────────────────────────────────────────────────
  — Никаких «здесь будет...», «...остальное без изменений», «TODO».
  — Никаких пояснений от автора ответа внутри codefence.
  — Никаких пустых файлов-заглушек.
  — Каждый файл — валидный, завершённый, готовый к сохранению.

ПРАВИЛО 7. БАЛАНС CODEFENCE.
─────────────────────────────────────────────────────────────────
Внутри каждого markdown-файла все внутренние ``` должны быть
сбалансированы: на каждый открывающий ``` — ровно один закрывающий.
Перед публикацией пересчитай их.

ПРАВИЛО 8. СОХРАНЯЙ ВСЕ ТЕХНИЧЕСКИЕ ДЕТАЛИ.
─────────────────────────────────────────────────────────────────
  — Все эндпоинты, все настройки, все команды БД.
  — Все внутренние ссылки вида [text](path).
  — Все бейджи, таблицы, эмодзи.
  — Ничего не выдумывай — только перераспределяй контент из README.

ПРАВИЛО 9. НЕ ССЫЛАЙСЯ НА ФАЙЛЫ, КОТОРЫХ НЕТ.
─────────────────────────────────────────────────────────────────
Если в README упоминается docs/adr/0005-... — убедись, что он есть
в списке файлов. Если нет — удали ссылку или замени на существующий.

САМОПРОВЕРКА ПЕРЕД ПУБЛИКАЦИЕЙ (обязательно, для каждого файла)
═══════════════════════════════════════════════════════════════════

Перед тем как вывести файл, мысленно ответь на 6 вопросов:

  1. Весь ли файл внутри ОДНОГО codefence?                  [ДА/НЕТ]
  2. Есть ли между codefence одного файла хоть один символ
     (кроме перевода строки)?                                [НЕТ/ДА]
  3. Есть ли внутри файла строки, начинающиеся с ```?        [ДА/НЕТ]
  4. Если на (3) — ДА, то внешний codefence ```` (4 кавычки)? [ДА/НЕТ]
  5. Сбалансированы ли все внутренние ```?                   [ДА/НЕТ]
  6. Нет ли «висящего» текста после закрывающего codefence
     до следующего заголовка файла?                          [НЕТ/ДА]

Если хотя бы один ответ не совпадает с ожидаемым — переделай файл.
