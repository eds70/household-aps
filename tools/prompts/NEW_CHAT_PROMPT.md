═══════════════════════════════════════════════════════════════════
ПРАВИЛА РАБОТЫ

1. ЛИСТИНГ ИСПРАВЛЕННЫХ ФАЙЛОВ — ВСЕГДА ПОЛНОСТЬЮ.

7. РАЗДЕЛЕНИЕ «ВХОД» / «ВЫХОД».
   Формат подачи файлов (теги, вложения, текст) — на стороне
   пользователя, ассистент принимает любой.
   Формат вывода (codefence, полный листинг, остановки) —
   на стороне ассистента, единый для всех входов.
   Смешивать эти два уровня в одном правиле нельзя.

═══════════════════════════════════════════════════════════════════
ФОРМАТ ПРИЛОЖЕНИЙ
═══════════════════════════════════════════════════════════════════

Файлы можно передавать двумя способами:

  (а) ТЕГАМИ в тексте сообщения:

      <file name="README.md">
      ...содержимое...
      </file>

      <file name="docs/ROADMAP.md">
      ...содержимое...
      </file>

      <file name="project_dump.txt">
      ...содержимое...
      </file>

  (б) ВЛОЖЕНИЕМ с диска — имя файла = имя вложения.
      Путь указывается в сопроводительном тексте сообщения, например:
      "Файлы во вложениях: README.md, docs/ROADMAP.md,
       CHANGELOG.md, project_dump.txt (--outline)".

Смешивать оба способа для одного файла не нужно —
это создаёт риск двух версий одного документа.

Приоритет:
  README.md и ROADMAP.md — обязательны.
  CHANGELOG.md — желателен.
  project_dump.txt — в режиме --outline (достаточно для обзора).
  ТЗ.txt — по запросу, если нужно сверить с исходными требованиями.

При вложении с диска:
  - сохраняй структуру путей в именах (docs_ROADMAP.md
    или явно указывай путь в сопроводительном тексте);
  - если файлов больше 5 — перечисли их списком в тексте,
    чтобы ассистент не угадывал назначение.
