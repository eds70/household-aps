ПРАВИЛО 2. ФОРМАТ ЗАГОЛОВКА ФАЙЛА
═══════════════════════════════════════════════════════════════════

Заголовок файла — СТРОГО отдельной строкой ПЕРЕД codefence, ровно так:

  ## Файл N: <путь/к/файлу>

Примеры:
  ## Файл 1: README.md
  ## Файл 2: CHANGELOG.md
  ## Файл 11: docs/adr/README.md
  ## Файл 16: docs/adr/0005-new-decision.md

Никаких «Файл 1 — ...», никаких «### Файл 1», только `## Файл N: путь`.

═══════════════════════════════════════════════════════════════════
ПРАВИЛО 3. ВНЕШНИЙ CODEFENCE — ВСЕГДА ЧЕТЫРЕ КАВЫЧКИ
═══════════════════════════════════════════════════════════════════

Внутри КАЖДОГО из 15 файлов есть вложенные codefence (примеры
команд, SQL, JSON, PowerShell, Python, TypeScript). Поэтому:

  — Внешний codefence ВСЕГДА ```` (четыре кавычки), НИКОГДА ```.
  — Язык указывается СРАЗУ после открывающих четырёх кавычек.
  — Закрывающий внешний codefence — ровно ```` (четыре кавычки)
    на отдельной строке.

Причина: внутренний ``` закрывает внешний ```, и весь последующий
текст выпадает из codefence. Это ЗАПРЕЩЕНО.

Язык внешнего codefence:
  — Markdown-файлы    → `markdown` (или `md`).
  — SQL-файл целиком  → `sql`.
  — JSON-файл целиком → `json`.
  — Всё остальное     → `markdown`.

═══════════════════════════════════════════════════════════════════
ПРАВИЛО 4. ВНУТРИ CODEFENCE — РОВНО СОДЕРЖИМОЕ ФАЙЛА
═══════════════════════════════════════════════════════════════════

  — Никаких «здесь будет...», «...остальное без изменений», «TODO».
  — Никаких пояснений от автора ответа внутри codefence.
  — Никаких пустых файлов-заглушек.
  — Каждый файл — валидный, завершённый, готовый к сохранению.
  — Все внутренние ``` должны быть сбалансированы: на каждый
    открывающий ``` — ровно один закрывающий. Пересчитай их
    перед публикацией.

═══════════════════════════════════════════════════════════════════
ПРАВИЛО 5. БАЛАНС CODEFENCE ВО ВСЕХ ФАЙЛАХ
═══════════════════════════════════════════════════════════════════

Перед публикацией КАЖДОГО файла мысленно ответь на 6 вопросов:

  1. Весь ли файл внутри ОДНОГО codefence?                   [ДА/НЕТ]
  2. Есть ли между codefence одного файла хоть один символ
     (кроме перевода строки)?                                 [НЕТ/ДА]
  3. Есть ли внутри файла строки, начинающиеся с ```?         [ДА/НЕТ]
  4. Если на (3) — ДА, то внешний codefence ```` (4 кавычки)? [ДА/НЕТ]
  5. Сбалансированы ли все внутренние ```?                    [ДА/НЕТ]
  6. Нет ли «висящего» текста после закрывающего codefence
     до следующего заголовка файла?                           [НЕТ/ДА]

Если хотя бы один ответ не совпадает с ожидаемым — переделай файл.

ПРАВИЛО 10. ПОШАГОВЫЙ ВЫВОД С ОСТАНОВКОЙ ПОСЛЕ КАЖДОГО ФАЙЛА
═══════════════════════════════════════════════════════════════════

Ты выводишь файлы НЕ все сразу, а ПО ОДНОМУ.

Порядок действий для каждого файла:

  1. Выведи ОДИН файл строго по формату:
       ## Файл N: <путь/к/файлу>
       ````markdown
       <весь текст файла>
После закрывающего ```` — напиши ровно одну строку:
Файл N (<путь>) опубликован. Жду команду для вывода
следующего файла (<следующий_файл>).

Остановись и жди команду «ок» (или «ok», или «дальше»).

После команды — выведи следующий файл.

В конце, после последнего файла — выведи сводную таблицу:

#	Файл	Статус
1	README.md	✅
...	...	...
Публикация завершена.
